# База данных и дополнительные товары

## Миграция рекомендаций, истории и популярности

Для существующего магазина сначала сохраните резервную копию MySQL, затем выполните из корня проекта:

```powershell
php database/migrate-product-discovery.php
```

Если CLI PHP не загружает MySQL автоматически:

```powershell
php -d extension_dir='E:\Programs\PHP\ext' -d extension=pdo_mysql database/migrate-product-discovery.php
```

Используется подключение из `src/config/Database.php`; обёртка доступна только в CLI. Тот же `migrate-product-discovery.sql` можно импортировать через MySQL-клиент, **выбрав действующую базу**. Требуется MySQL 8.0+.

Миграция не удаляет записи и не изменяет прежние поля товаров, заказов, корзин, отзывов или галерей:

- добавляет `products.orders_count` — `INT UNSIGNED NOT NULL DEFAULT 0` и индекс `idx_products_popularity`;
- при первом запуске назначает воспроизводимую учебную популярность `20 + MOD(CRC32(slug), 481)` плюс число существующих неотменённых заказов с товаром;
- заполняет только промежуточные `NULL`: повторный запуск и продолжение после прерывания сохраняют уже назначенные значения, включая нули;
- создаёт пустую таблицу `product_views` с уникальной парой `(user_id, product_id)`, временем последнего просмотра `DATETIME(6)` в UTC и индексом последних просмотров; внешние ключи удаляют историю при удалении пользователя или товара.

`orders_count` учитывает **заказы с товаром, а не число штук**. Оформление прибавляет один раз на товар внутри транзакции; отмена вычитает один, восстановление возвращает его. Повторный статус и остальные переходы не меняют популярность. Новые товары админки начинают с нуля; обычное редактирование товара не меняет счётчик. Сортировка «По популярности» использует убывание `orders_count`, затем ID, и совместима с фильтрами, поиском, пагинацией и API.

История сохраняет до 30 уникальных товаров аккаунта, профиль показывает последние 12. Повторное открытие перемещает товар вперёд. Гостевые просмотры хранятся в сессии и объединяются с историей аккаунта при обычном и API-входе; более новый просмотр аккаунта не затирается. Товары из чужой истории, скрытые и неактивные товары не выводятся.

Рекомендации главной и профиля учитывают давность просмотра и категории: точная подкатегория имеет больший вес, чем соседние из того же корня. В наличии и непросмотренные альтернативы имеют приоритет; далее учитываются выбор магазина, число заказов и рейтинг. Без истории доступна общая подборка. Похожие товары ограничены категорией и типом товара, ранжируются по совпадающим характеристикам и близости цены, без случайной выборки. Комплекты кастомной СЖО не смешиваются с водоблоками и фитингами.

## Дополнение существующего каталога

`catalog-products.json` содержит **19 дополнительных товаров** с русскими описаниями, характеристиками, демонстрационными ценами, остатками и количеством заказов. При исходных 14 товарах каталог после импорта содержит **33 активных товара**.

В набор входят процессоры, видеокарты, материнские платы, DDR5-память, блок питания, корпус, воздушный кулер и готовые СЖО. Отдельная подкатегория `cooling/custom-water-cooling` содержит два комплекта кастомного охлаждения **Corsair XH305i RGB PRO** и **XH303i RGB PRO**, CPU-водоблок XC7 RGB PRO, фитинги и сливной кран. Наборы для самостоятельной сборки не обозначаются как готовые AIO-системы.

Запуск из корня проекта **после миграции выше** (или восстановления обновлённой структуры):

```powershell
php database/seed-catalog.php
```

Если расширение MySQL не подключено в CLI PHP, загрузите его явно (путь зависит от вашей установки):

```powershell
php -d extension_dir='E:\Programs\PHP\ext' -d extension=pdo_mysql database/seed-catalog.php
```

Используется подключение магазина из `src/config/Database.php`. Команда доступна только в CLI и **не удаляет и не обновляет существующие записи**:

- категории определяются по `slug`, а не по фиксированным ID; недостающие родители и подкатегории создаются;
- товар с уже существующим SKU **или** slug пропускается целиком, включая его фотографии и характеристики;
- перед записью проверяются данные, наличие и формат локальных изображений и миниатюр;
- все добавления выполняются одной транзакцией; ошибка откатывает новые записи;
- повторный запуск не создаёт дубликаты и не заменяет изменения, сделанные через админку;
- учебные `orders_count` новых товаров совпадают с формулой миграции; счётчики существующих товаров не перезаписываются;
- заказы, корзины, отзывы и пользователи не изменяются.

Тесты: `tests/catalog-seed.php`, только на изолированной SQLite-базе, без доступа к рабочей MySQL. Подробности запуска — в `tests/README.md`.

## Фотографии и источники

В `public/images/products/` добавлены **36 фотографий в WebP**, в `public/images/products/thumbs/` — их 36 миниатюр. Полные изображения имеют не более 1800 пикселей по длинной стороне, миниатюры — не более 420; пропорции и прозрачность сохранены. Исходные изображения других товаров не заменяются.

Для каждого товара поле `source_page` хранит страницу модели, а для каждого изображения `source_url` — адрес использованного файла. Источники:

Сайт отдаёт изображения локально; импорт не скачивает файлы из интернета. Фотографии принадлежат производителям и авторам обзоров. Указание источника не является лицензией: перед публичным или коммерческим использованием нужно проверить разрешение на публикацию. Цены, остатки и число заказов в наборе учебные, не являются актуальными предложениями производителей или реальной статистикой продаж.

## SQL-файлы

`pc_components_schema.sql` и `pc_components_data.sql` предназначены для восстановления исходной структуры и данных **в пустой базе**; `pc_components.sql` — объединённый вариант. Дополнительный каталог добавляется после восстановления отдельной CLI-командой выше, поэтому не зависит от ID и не требует перезаписи пользовательского дампа.

Оба варианта восстановления уже содержат `orders_count`, индекс популярности и `product_views`; данные назначают учебные счётчики с учётом исходных заказов, история остаётся пустой. Для действующего магазина используйте **миграцию**, а не восстановление. `pc_components_data.sql` содержит исходные 14 товаров и не предназначен для повторного импорта поверх пользовательских данных.

Проверки алгоритмов — `tests/product-discovery.php` и `tests/product-discovery.test.cjs`. Дополнительный `tests/mysql-product-discovery.php --isolated` проверяет миграцию, восстановление и модели только в новых временных MySQL-базах; порядок запуска описан в `tests/README.md`.

**Не используйте `products_data.sql` для дополнения действующего магазина:** старый сид очищает товары и связанные таблицы. Для безопасного расширения каталога используйте `seed-catalog.php`.
